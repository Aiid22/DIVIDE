# Engineering assumption ledger

| ID | 工程假设 | 影响 | 解除条件 |
|---|---|---|---|
| EA-001 | OCR 规则约束 beam 默认 `B=64`。 | 召回、时延。 | 获得作者配置或在开发集上预注册标定。 |
| EA-002 | 深度、大小、压缩比、像素、帧数、查询与超时预算。 | 可处理载体范围。 | 公开作者预算或完成安全/性能实验。 |
| EA-003 | 验证阈值及载体、字段、上下文、恢复权重。 | precision/recall。 | 严格隔离测试集后在开发集标定。 |
| EA-004 | OCR 几何空格阈值和字符替换惩罚。 | 图片恢复率。 | 用标注 OCR 数据消融并报告。 |
| EA-005 | GitHub Base62 默认字母表为 `0-9A-Za-z`。 | checksum 接受/拒绝。 | 用供应商独立向量确认字母表及补零。 |
| EA-006 | 选择 Gitleaks v8.30.1 完整配置（commit `83d9cd684c87d95d656c1458ef04895a7f1cbd8e`）作为可重复代理；论文未公开精确规则 commit。 | 与论文规则语料的等价性。 | 获得作者使用的精确 commit。 |
| EA-007 | 编码证据的数值聚合方式。 | 非 UTF 文本提取。 | 获取作者公式或独立标定。 |
| EA-008 | RelatedGroup 的字段命名与同父对象启发式。 | 分片恢复率。 | 用论文数据的关系标注验证。 |
| EA-009 | `no-media` 在 handler 调度前跳过图片、音频和视频对象，仍保留 PDF 文本层。 | 消融边界。 | 与论文作者的媒体定义和计时边界对齐。 |
| EA-010 | Gitleaks 的 RE2 规则由 Python `regex` 引擎执行，并显式把 `\\z` 转为 `\\Z`。 | 少量正则语义可能不同。 | 使用 Gitleaks/Go RE2 作为同进程规则执行后端或逐规则等价性验证。 |

任何实验结果必须携带配置哈希、规则哈希和本登记版本，禁止把上述值描述为论文原参数。
